# Linux execution and GPU rasterization implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Execute existing SDK applications through an optional hardware GPU command renderer, and supply an honest Linux/Wayland acceptance entry point.

**Architecture:** Shared validated scene and resource checks feed CPU or integer GPU compute. GPU pixels are read back into the existing native presentation path. Linux acceptance distinguishes headless and Wayland.

**Tech Stack:** Rust 1.99.1, wgpu =27.0.1, pollster =0.4.0, existing Kotlin 2.3.20/Wasm SDK.

**Spec:** docs/superpowers/specs/2026-10-24-linux-gpu-design.md

## Global Constraints

- Preserve SDK v1/v2, Wasm imports and launcher-owned grants.
- CPU stays default; GPU feature and CLI choice are explicit, with no silent fallback.
- Keep 32,000,000 CPU work bound; experimental GPU candidate checks bounded at 64,000,000.
- Identify adapter and timing scope; CPU device selection is rejected.
- No Linux/Wayland pass claim without actual execution.
- No Git repository exists; do not create one or make commits for this work.
