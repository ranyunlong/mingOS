# 父侧应用安装登记设计

日期：2026-10-30。

## 目标

为 Linux 桌面增加一个由可信父进程持有的本地安装登记账本。登记把应用 `packageId`、三段版本号和已加载 manifest/Wasm 的内容指纹绑定起来，使桌面在启动前能够拒绝未登记、已卸载或内容被替换的包，并为后续真实签名发布系统提供明确的接入边界。

## 信任边界

- 登记根目录必须由父进程预先创建，使用绝对路径、当前父进程拥有者和仅拥有者权限。
- 登记文件由父进程以临时文件、`sync_all`、原子 rename 和目录同步写入。
- 进程生命周期内持有登记根排他锁；第二个桌面或安装管理器不能同时修改同一登记根。
- 登记内容指纹只证明“当前可信父进程登记过这份内容”，不证明发布者签名、证书链、远程仓库或供应链来源。

## 格式与生命周期

登记文件使用固定头 `ming-installed-packages-v1`，每个包一条按 `packageId` 排序的记录：

```text
packageId<TAB>active|removed<TAB>version<TAB>lowercase-sha256
```

安装新包创建 `active` 记录；相同版本和指纹重复安装幂等；同一 `packageId` 只有更高版本可更新，降级被拒绝。卸载只把记录改为 `removed`，不删除应用私有目录或公共目录数据；相同包可由父进程再次安装恢复为 `active`。桌面启动时再次加载包并与 `active` 记录的版本和指纹完全比较。

## 接入方式

桌面开发入口增加 `--install-root <absolute-directory>`。配置该选项时，catalog 仍负责开发期的窗口和包路径配置，但每个包还必须出现在登记账本中并精确匹配。未配置时保留 schema v1/v2 开发兼容行为，不能将其称为生产安装信任。

登记根同时保存父侧加载后的包内容，目录按 `packageId/版本-指纹` 分代，不覆盖历史版本。`install_from_manifest` 先完整加载并校验源包，再把规范化 manifest 和 Wasm 写入新的私有目录，完成同步后发布登记记录。catalog schema v3 只接受 `packageId`，从活动登记解析内容路径，不再直接信任任意 catalog manifest 路径；v1/v2 仍是开发兼容格式。

## 非目标

本阶段不实现发布者签名、密钥轮换、远程仓库、用户确认 UI、多用户身份、更新迁移脚本或卸载数据清理策略。上述能力必须在真实安装服务和系统信任根阶段单独设计与验收。
