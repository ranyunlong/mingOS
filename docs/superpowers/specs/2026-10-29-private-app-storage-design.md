# 应用私有存储方向

> 2026-10-30 用户澄清：应用默认可访问自己的私有目录，不需要用户授权；公共目录访问才需要授权。本文中早期有关私有目录授权、撤销和 `privateStorage` 声明的设计已被此规则取代，以下阶段记录保留历史背景，不代表当前权限模型。

## 当前权限模型（2026-10-30）

- 应用默认获得与自身安装包身份绑定的私有目录；目录按应用身份隔离，不需要 `privateStorage` manifest 声明或用户弹窗。
- 公共目录是独立的共享命名空间。应用只能在可信父进程产生用户授权后获得 `PublicFileSession`；未授权默认拒绝。
- 公共授权支持持久化、显式撤销和运行代失效；撤销私有授权不会影响公共授权，反之亦然。
- 公共目录仍只能通过受限相对路径访问，不能获得宿主路径、其他应用私有目录或任意文件系统能力。
- 当前已完成父侧公共会话、公共 RPC、授权请求、Kotlin SDK v2 类型化接口、真实桌面控制器授权/拒绝验证，以及独立新盘 kernel 公共目录诊断。kernel 证据验证的是 guest-seeded preauthorization，不替代真实物理用户输入或可信安装身份验收。

日期：2026-10-29。用户要求：用户授权应用访问存储后，应用可读写自己的私有存储，应用之间隔离。现有 SDK6 的 AppData 只有 8 个固定槽，不是完整文件目录；本设计不能把已有槽接口或静态 catalog 配置称作完成的用户授权。

## 授权与身份

- 应用在 manifest 中以 `"privateStorage": true` 显式声明私有存储需求，仅 SDK 6 支持；未声明默认为 false，旧包无需修改。声明本身不是用户授权，且被纳入内容指纹；未声明的包不能通过新式授权接口获取会话。
- 系统可信的安装记录确定应用身份，应用提供的名字、路径、manifest 和 worker 请求本身不授予权限。安装和更新必须将身份与可信发布者或等价的安装授权绑定；现有未签名包仅是开发环境，不能声称具备生产身份认证。
- 用户允许后，系统向该应用的当前运行代授予自己的私有目录读写权限。拒绝或撤销后请求失败；撤销等待正在进行的操作结束，再拒绝后续操作。授权决策需要可信系统 UI 和持久化记录，用户需能查看和撤销；不能仅凭 catalog 字段冒充用户同意。
- 正常退出和进程崩溃不删除文件。重启后，在仍有授权的前提下重新打开同一安装身份对应的目录；旧运行代持有的授权不可恢复。卸载数据保留或删除应由明确的卸载交互决定。
- 同一设备不同用户或不同安装身份的目录和授权彼此隔离。当前系统尚无多用户或可信安装管理，现阶段不得假设自报的包 ID 足以提供这两项保证。

## 文件能力

- 应用通过 Ming SDK 使用自己的私有相对路径创建目录、列目录、读取、写入、重命名和删除；不得取得宿主路径、系统根目录或其他应用目录。写入应有明确的原子提交和错误语义；目录同步结果与断电持久性分开记录。
- 父进程持有目录句柄，worker 只获得受控能力。路径解析逐组件拒绝绝对路径、`..`、符号链接以及特殊文件；限制路径长度、目录深度、单次消息大小和同时打开的句柄。配额由系统统一实施，不能只限制 SDK 单次请求，必须覆盖所有写入和并发运行代。
- 私有文件路径最多 1024 UTF-8 字节、16 个组件、每组件最多 255 字节；拒绝空组件、`.`、`..`、NUL、反斜杠和 `.ming-data-` 保留前缀。Linux 父侧文件原型将校验与逐级 `O_NOFOLLOW` 目录句柄结合；文本校验本身不能提供隔离。
- 旧 SDK6 槽和旧 catalog 键继续可用，禁止静默搬迁、覆盖或把旧目录冒充新目录。新目录命名应可稳定重建、区分不同身份并与旧键命名空间分离。

## 基础实现及阶段记录

以下条目按实现阶段记录；其中“尚未接入”等描述仅表示该阶段的状态，以本节的桌面接入段和最新进展为准。

`AppDataRoot::grant_package` 使用已验证的包 ID 生成独立、可逆的文件系统组件，复用现有父侧槽存储与撤销。`PackageStorageAuthority` 是可信父进程内存中的授权协调器：初始拒绝，可信父进程确认用户同意后授权；撤销阻止新授权并等待所有已发出授权的进行中操作结束，再使其失效。同一应用同时存在的授权上限为 64，释放后可再申请；不同应用相互独立。并发申请和撤销通过同一把锁排序。

Linux 新增持久模式，将授权记录写入系统专用目录；重新打开时严格校验记录，跨进程文件锁阻止两个持久协调器同时持有该记录。管理器撤销活跃授权后显式释放锁，避免 fork 子进程暂时继承描述符而延迟释放；该锁仍要求所有可信调用方遵守单协调器约束。授权或撤销返回持久化和目录同步回执；目录同步未确认时不能宣称断电后一定保留。撤销写入失败时，当前进程立即拒绝访问，但磁盘旧授权可能残留，必须重试并确认成功。Windows 尚无此持久模式。

Linux 另提供内容绑定授权：可信父进程对加载后的 manifest 字段和完整 Wasm 计算带版本域分隔的 SHA-256，授权记录 v2 持久化该指纹。新式文件会话只接受完全匹配的包；旧的仅 ID 授权保留原有接口，但不能用于新式会话或 supervisor 启动。包内容变化时必须先撤销旧授权并重新明确批准，数据目录仍按包 ID 保留。v1 旧记录可读取，和 v2 绑定记录混存时保留各自类型；旧程序无法读取 v2，故不能假定可无损降级。记录的内容指纹不是发布者签名或可信安装证明；调用者必须从可信安装和用户确认流程取得包，不能把自报的 manifest 当作批准。

可信父进程的 `StorageConsent` 可准备待确认的包快照，提供 ID、版本、指纹和是否与现有授权冲突；拒绝或丢弃提示不授权，普通允许不能覆盖冲突。已授权的精确内容可恢复会话，新的允许结果包含持久化回执。测试验证提示期间磁盘包被替换时只授权原快照，以及竞争授权不会被覆盖；测试还将模拟允许后的会话接入真实 Kotlin supervisor。冲突的撤销和重新批准交互仍待实现。

Linux 桌面在配置 `--data-root` 且应用声明私有存储时接入提示及会话：首次请求需要原生窗口实际呈现提示后，鼠标在同一按钮完成按下与释放才能允许或拒绝；提示期间阻止普通脚本动作和应用输入，并暂停后续自动启动。离屏模式不能批准新授权，未授权的应用以无存储权限运行；已有精确内容授权可恢复。提示显示完整包 ID、SHA-256、版本及未验证发布者提示；冲突提示没有普通允许按钮。测试通过桌面控制器模拟呈现和点击后启动真实 Kotlin worker，并验证重开后的数据；离屏默认拒绝也由真实 worker 验证。CPU 绘制及最小尺寸边界测试、GPU 功能编译和 WGSL 静态校验通过，但真实窗口呈现、物理输入和 GPU 像素一致性尚未验收。系统安装身份、授权查看与撤销、包冲突处理、多用户及数据根单权威约束仍未完成，不能声称整体存储能力已交付。

最新进展：可信父侧可按实际授权代创建管理快照并撤销，旧确认不能撤销之后重新授予的同一包。撤销写入失败或目录同步未确认时，该进程内保留失效代并禁止重新授权；可用同一快照重试，确认同步后才允许新授权。写入失败后若未成功重试就退出，磁盘仍可能保留旧授权，重启后可能恢复；此机制不解决该情况。Linux 桌面应用图标上的 `S` 控件可打开授权管理；无授权或存储不可用会显示对应状态。控制器测试模拟原生呈现、匹配的按下释放和撤销后重开，并验证写入失败及重试；尚未做真实窗口或 GPU 像素验收。

类型化 SDK 的读写、分页列目录、目录创建和删除、文件重命名和删除已由真实 Kotlin worker 做功能诊断，覆盖隔离、大文件分块、特殊文件名、缺失文件和撤销后拒绝；异常宿主回复等错误路径仍未完整覆盖。当前 JSON 依赖显著增大 Wasm，debug worker 的首请求时间超过原 20 秒测试等待；诊断使用更长等待，不代表性能验收通过，生产 release 与严格隔离尚待测量。

该协调器不验证用户同意，也不是授权 UI；持久模式的文件锁不能阻止可信调用者另建内存协调器或直接使用底层 `grant_package`。待桌面接入时必须使同一数据根的所有新存储操作经过同一个权威实例，并由可信 UI 产生授权决定。当前也没有签名绑定、完整目录操作或桌面接入，因此不是面向用户的私有文件功能。Linux 测试覆盖不同包、旧键隔离、并发撤销、持久授权记录损坏和写入失败，以及真实子进程重开和跨进程锁。

Linux 父侧现有私有文件原型支持建立和列举目录、删除空目录、整文件读取、原子替换和删除、文件不覆盖重命名，位于包目录的独立 `files` 命名空间；每次操作检查授权，协调器锁串行化操作与撤销。列举不显示内部临时文件；重命名依赖 Linux `renameat2(RENAME_NOREPLACE)`，返回双目录同步结果。单文件和应用总量最多 8 MiB、最多 1024 个文件和目录；旧数据槽仍限制 64 KiB。写入前扫描并校验所有条目，异常条目拒绝操作。该配额只在所有访问都经过同一个协调器且其他可信进程不直接更改目录的条件下成立。系统尚未强制满足该条件；现阶段没有目录重命名或真实桌面授权，不能视为用户可用的完整文件系统。

父侧 `PrivateFileSession` 将已授权的包身份绑定到运行会话，调用者操作时无需再传包 ID。关闭会话等待该会话进行中的操作并使其所有克隆失效；撤销授权后，即使重新授权，旧授权代的会话仍不可用。同一包最多保留 64 个尚未释放的会话。会话已接入测试中的 worker 和 supervisor，但桌面尚未发放；包 ID 必须由可信安装记录而不是应用请求确定，现有代码尚不验证发布者身份。

Linux 父侧新增 `PrivateFileRpc` 请求适配器，严格解析操作和字段，拒绝包身份注入，使用绑定的会话执行操作；单次读取、整文件写入或上传分块最多 64 KiB，目录按最多 32 项分页。`write_begin`、连续的 `write_chunk` 和 `write_commit` 可原子替换最多 8 MiB 的文件，`write_abort` 放弃暂存；提前提交保留暂存，正式提交失败则丢弃暂存。每个 RPC 对象及其克隆最多一个上传，进程内暂存预算为 64 MiB。会话关闭、对象释放或撤销后再次调用时释放暂存；单独撤销不会主动释放不再调用的会话的暂存。读取可按偏移分页，但当前实现每次在父侧读取整个文件；目录分页不是快照，目录改变时页之间可能变化。宿主消息分发已提供 `private_file_call` 路由，要求 SDK6 或更高、空参数及请求体，并在运行代结束时关闭会话；无会话时默认拒绝。

Linux worker 支持 SDK6 的可选导入 `ming_private_files_v1.call(input, length, output, capacity)`。输入是 UTF-8 JSON，输出缓冲区至少 90000 字节；负数表示错误，非负数表示写入缓冲区的 JSON 回复字节数。worker 在 RPC 前校验输入及输出内存范围和消息大小，拒绝附带异常 payload 的错误回复。Kotlin SDK 的 `MingPrivateFiles.call` 提供有界字节请求和独立的回复字节，但尚无类型化文件操作或 JSON 解析封装。真实 Kotlin/Wasm 应用已验证宿主默认拒绝；独立测试父进程显式授权两个身份，直接转发真实 worker 的 RPC 并验证文件读写、跨应用隔离、同进程管理器重开及撤销。该测试不经过桌面授权 UI 或 supervisor 消息循环；桌面没有发放会话，实际应用尚不能获得文件访问权限。

另有显式授权的 supervisor 单元集成测试：真实 Kotlin worker 经 supervisor 消息循环写入并读取私有文件，运行结束后会话失效；会话身份与实际加载的包 ID 不一致时在启动前拒绝。发放给 supervisor 的文件会话必须与实际包的内容指纹匹配，且同时绑定父进程提供的包快照；启动时比较已解析的 manifest 字段和完整 Wasm 字节，不一致则拒绝启动并关闭会话。这些检查不构成可信安装记录或发布者认证，可信调用方仍需确保快照来自用户确认的对象。测试中授权直接由父进程设置，桌面授权流程仍未实现。测试构建可通过环境变量指定 worker 二进制；生产构建仍固定使用当前宿主可执行文件。

## 后续验收

1. 完成可信安装身份、用户授权记录及撤销流程，确认未经授权和撤销后的请求都被拒绝。
2. 实现 SDK、RPC 和父侧文件目录操作及实际配额；测试路径穿越、符号链接、竞争、并发、目录和句柄限制、跨应用访问和失败后的数据完整性。
3. 用真实 Kotlin 应用验证两个应用的数据隔离、正常退出和故障后重启、授权撤销与再次授权；公共目录的真实 kernel 新盘预授权路径已验证，仍需补充真实物理用户授权和安装身份绑定。
4. 覆盖更新、卸载及多用户等安装生命周期后，才能声称实现了完整的应用私有存储；断电耐久性和物理设备分别验证。
