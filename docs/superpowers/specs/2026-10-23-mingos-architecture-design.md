# MingOS 架构设计草案

日期：2026-10-23。状态：总体方向已授权；具体技术处于原型验证阶段。

## 产品原则

Linux 提供硬件与基础系统；MingOS 定义桌面、SDK、应用执行模型和分发规则。以一致交互、可测性能、明确权限和可恢复更新为目标，不将外观相似等同于平台完成。

## 分层

| 层 | 职责 | 当前状态 |
| --- | --- | --- |
| Linux 基础 | 内核、驱动、启动、电源、网络底座 | 待选硬件与基础系统 |
| 原生服务 | 文件、网络、图形、音视频、凭据、资源管理 | 首先验证只读文件能力 |
| 合成器 | Wayland、窗口管理、显示输出、全局动画 | 后续阶段 |
| Shell | 启动器、Dock、工作区、通知、设置 | 后续阶段 |
| 应用平台 | 运行时、身份、生命周期、权限、SDK、包 | 当前开发重点 |
| 应用 | Kotlin 为主要语言，使用 Ming API | 首个控制台读取示例 |

图形后端与应用运行时分开验证。不能假定 Compose Desktop 可直接运行在自定义 WASI 宿主。全局效果由合成器负责，应用内部绘制由应用 UI 框架负责；资源通过批量命令或缓冲区传输，具体协议尚未冻结。

## 信任边界

普通应用和依赖是不受信任输入。运行时只链接固定允许的函数导入，拒绝 WASI、未知模块以及内存/表/全局变量导入。应用不持有宿主文件路径、Node API 或系统服务管理权限。

宿主从可信启动配置读取应用清单和授权；应用清单可声明需求，不能自行授予权限。文件能力使用启动时打开的文件描述符，应用只接触本次运行的整数句柄。宿主不接受来自应用的路径或 AppID，不把句柄直接映射成操作系统文件描述符。

父进程管理身份、授权、文件和运行期限；子进程仅运行 Wasm 并发起受控请求。原型采用受限 Node 子进程，不提供生产 Linux 沙箱保证。V8/Node、解析器、宿主服务和操作系统均属于需持续评估的可信计算基础。

## 第一阶段行为

- 可信启动者指定包与资源授权；包清单自身不能提供授权路径。
- 本地可读普通文件以命名资源形式授予，限制文件尺寸、模块尺寸、日志和请求数量。
- 应用通过 SDK 打开资源、读取长度/字节、输出诊断结果、结束运行。
- 未授权资源返回明确错误码；无效句柄不映射到宿主资源。
- 未知导入、WASI 文件/网络能力、损坏模块、异常退出和超时给出可诊断错误。
- 子进程异常不结束宿主；父进程回收子进程和文件描述符。

## 第一阶段安全限制

不保证阻止 V8/Node 漏洞；Node 堆限制不是总 RSS 或 Wasm 线性内存的硬上限；不覆盖生产签名、发布者验证、可撤销授权、用户身份、多租户、不可信包路径/符号链接竞态和运行中内容变更的全部风险。可信启动配置与工作区是原型前提。最终 Linux 阶段需建立独立进程/挂载/网络隔离、系统调用限制、凭据和 cgroup 资源限制，并针对真实攻击面验证。

## SDK 演进

后续逐步提供 UI、窗口、生命周期、文档、存储、输入法、通知、剪贴板、拖放、网络、媒体、凭据和无障碍。协议版本独立于实现版本；先保留实验 API 身份，稳定后再承诺兼容。系统应用尽量使用公开 API，额外权限需显式配置。

## 系统可靠性

应用包与用户数据分离。系统更新需验签、启动成功确认和失败恢复；数据迁移必须单独设计可兼容或可恢复路径。一个应用或 Shell 失败不应导致整个会话不可用。浏览器引擎和原生扩展需要独立权限及隔离设计。

## 路线图与退出条件

1. 应用运行与 SDK 边界：真实 Kotlin/Wasm 应用读取授权资源，越权、错误和超时测试通过。
2. 图形原型：图片查看器跑通文件、绘制、输入；记录启动、内存、输入延迟和帧时间。
3. 最小桌面：自有合成器、多窗口、Shell、中文输入和基本恢复。
4. 开发平台：组件、SDK 工具、包管理、版本测试与独立开发流程。
5. 独立系统：固定硬件启动、浏览器、设置、更新和恢复，可完成目标日常任务。
