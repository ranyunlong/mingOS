# 安装生命周期与应用数据策略

日期：2026-10-30。

## 当前策略

- 卸载先撤销安装登记，不删除应用私有数据；同一 `packageId` 重新安装后继续使用原私有目录。
- 已安装包的历史内容目录也不因卸载立即删除，便于父侧保留可审计的版本内容。
- 公共目录是共享命名空间，卸载某个应用不能删除公共文件；公共授权的撤销由独立授权流程处理。
- 永久删除私有数据必须是独立的破坏性操作，不能由普通卸载隐式触发。

## 父侧清除边界

`PackageStorageAuthority::purge_private_data(packageId)` 是父侧内部清除入口：

- 只接受合法的已验证包身份格式；
- 仍有私有运行代或旧式私有 grant 时返回 `Denied`，不部分删除；
- 使用 Linux pinned directory descriptor、`O_NOFOLLOW` 和逐级 `unlinkat`/`AT_REMOVEDIR` 递归删除；
- 删除完成后同步父目录；缺少私有目录返回 `false`，成功删除返回 `true`；
- 只删除该包的私有命名空间，不触碰公共目录或兄弟应用目录；
- 删除后旧私有运行代失效，重新安装流程必须重新创建运行代。

本阶段只提供父侧安全原语和回归测试，尚未接入真实卸载 UI、安装服务事务或多用户身份。安装登记与数据根之间仍需要后续的系统级协调，不能把本 API 单独称为完整卸载流程。

## 安装服务组合

父侧安装登记现在提供 `uninstall_with_data_policy`：

- `PreservePrivateData` 是默认路径，只撤销活动登记，不触碰私有目录；
- `PurgePrivateData` 是显式破坏性路径，先完成卸载登记，再调用数据 authority 清除私有目录；
- 清除失败不会恢复已撤销的登记，也不会删除部分数据，结果保持为“已卸载、数据保留”，允许用户关闭运行代或撤销旧 grant 后重试；
- 已卸载登记仍可执行一次显式清除，但普通卸载不会隐式触发清除；公共目录和公共授权不由该组合接口删除。

这仍是父侧服务 API，不是桌面菜单、系统确认对话框或多用户安装身份实现。

## 验收

覆盖一个应用存在私有文件、兄弟应用仍有文件、公共目录存在共享文件以及私有运行代仍存活的情况。测试确认活跃运行代阻止清除；关闭后私有目录被清除，兄弟私有数据和公共文件保持可读。
