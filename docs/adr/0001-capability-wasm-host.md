# ADR 0001：以能力式 Wasm 宿主验证应用边界

日期：2026-10-23。状态：仅接受为第一阶段原型方案。

## 背景

严格 SDK-only 与 Kotlin/高性能桌面组合尚需验证。普通 JVM 应用不能仅靠 SDK 封装满足外部接口限制。项目尚无 Linux 发行版、图形框架或硬件选型。

## 决策

采用 Kotlin/Wasm 的实际编译产物作为示例应用；以 Node.js 24 的 WebAssembly 引擎建立跨平台开发宿主。生产代码只用 Node 内置模块，测试用 node:test，无 npm 运行时依赖。

原型不实例化 node:wasi，不提供 WASI 文件系统、环境、进程或网络接口。模块只允许 ming_v1 下列明的函数导入。子进程通过匿名管道与父进程交换消息。父进程持有文件描述符、身份和授权，子进程不接收宿主路径。对子进程启用 Node 权限模式、关闭原生扩展、设置堆提示与超时。

首版 SDK 使用整数和有界只读资源，以降低 Kotlin/Wasm 跨边界对象布局复杂度。字节读取仅用于验证，不作为最终文件/图形吞吐量协议；下一阶段评估批量传输与共享缓冲区。

## 取舍

Node/V8 是开发宿主选择，不是 MingOS 生产运行时承诺。进程分离降低原型耦合，无法代替 Linux 内核隔离。允许的纯函数宿主导入也属于 SDK，普通 WASI 导入默认拒绝。

Kotlin 工具链与 Gradle 版本固定，真实构建由网络依赖或本地缓存提供。标准库初始化所需的导入必须逐项评估；不能为让示例跑起来而直接接入完整 WASI。

## Linux 验收

移植后必须验证命名空间、文件系统、网络、系统调用、资源硬限制与真实进程回收。Windows 测试只证明当前宿主和 Wasm 接口行为，不能声称完成 Linux 安全验证。

## 2026-10-23 宿主语言取舍补充

用户询问为何使用 JS。JS 是当前开发宿主和测试工具的实现选择，原因是本机已有 Node/V8，可直接验证 Wasm 与 IPC；这不是用户指定语言，也不是生产操作系统技术栈承诺。代价是后续需要迁移宿主，且 Node 权限模型不能代替内核隔离。

生产 App Host 和系统服务优先评估 Rust；以可复用的 SDK ABI、模块导入白名单、能力语义和跨实现验收测试降低迁移成本。进入图形阶段前应复核运行时与 Rust 引擎对实际 Kotlin 产物（含 Wasm GC/异常特性）的支持。迁移成功的条件是同一个 Kotlin 产物在新宿主中通过授权、越权、故障和资源测试，并获得可接受的性能数据。不能仅因原型使用 Node 就持续扩大 JS 在系统核心中的范围。
